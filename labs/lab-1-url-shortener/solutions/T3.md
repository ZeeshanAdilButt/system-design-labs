# T3 solution: a shuffle that is not a shuffle

Try the task first: [YOUR-TURN.md](../YOUR-TURN.md#t3-a-shuffle-that-is-not-a-shuffle). The
fixed file is [t3_solution.py](t3_solution.py).

## Answer

In `shuffle`, each round threw away the old left half. The fix is one line:

```python
left, right = right, (left + _mix(right, key)) % HALF  # was: left, right = right, _mix(right, key)
```

## Why it works

A round of this shuffle (a Feistel network) must keep both halves' information: the new right
half is the old left half **plus** a hash of the old right half. Then it can be undone: if you
know the new halves you know the old right half (it is the new left half), so you can compute
the same hash again and subtract it from the new right half to recover the old left half. That
is exactly what the correct `unshuffle` does with `right - _mix(left, key)`.

Without the `left +`, the new right half depends only on the old right half. The old left half is
gone, and different inputs can reach the same output because `_mix` squeezes its result into only
238,328 values (`HALF`) and is not one-to-one. The hash itself never has to be one-to-one. The
plus is what makes the whole round one-to-one, whatever the hash does. Two counter values with the
same output would become two links with the same short code.
